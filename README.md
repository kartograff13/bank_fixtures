# Bank Fixtures - Анализ банковских операций
### Проект для анализа банковских транзакций с генерацией отчетов, аналитикой расходов и интеграцией с финансовыми API.

## 📊 Функциональность
### Основные модули
📈 Отчеты (reports) - Анализ расходов по категориям, дням недели и типам дней

🔧 Сервисы (services) - Дополнительные аналитические инструменты

🖥️ Представления (views) - Готовые данные для веб-интерфейсов

🛠️ Утилиты (utils) - Вспомогательные функции для работы с данными

### Ключевые возможности
- Анализ расходов по категориям за периоды

- Расчет кешбэка и инвестиционных накоплений

- Поиск транзакций по различным критериям

- Интеграция с курсами валют и биржевыми котировками

- Автоматическое сохранение отчетов в JSON формате

## ⚙️ Установка и настройка
### Предварительные требования
- Python 3.8+

- Poetry для управления зависимостями

### Установка
1. Клонируйте репозиторий:
```
git clone <repository-url>
cd bank_fixtures
```
2. Установите зависимости через Poetry:
```commandline
poetry install
```
3. Активируйте виртуальное окружение:
```commandline
poetry shell
```
### Настройка
1. Подготовьте файл с данными:

- Поместите Excel файл с транзакциями в папку data/operations.xlsx

- Формат данных должен соответствовать структуре Тинькофф банка

2. Настройте пользовательские предпочтения в user_settings.json:
```
{
  "user_currencies": ["USD", "EUR"],
  "user_stocks": ["AAPL", "AMZN", "GOOGL", "MSFT", "TSLA"]
}
```
3. Настройте API ключи (опционально):
- Создайте файл .env на основе .env.example

- Получите API ключ на Twelve Data

- Добавьте в .env: API_KEY=your_api_key_here

```commandline

```

#### Генерация отчетов
```
from src.reports import spending_by_category, spending_by_weekday

# Отчет по категориям

```
## 📋 Формат данных
### Входные данные (Excel)
#### Проект ожидает Excel файл со следующими колонками:
- Дата операции — дата, когда произошла транзакция.
- Дата платежа — дата, когда был произведен платеж.
- Номер карты — последние 4 цифры номера карты.
- Статус — статус операции (например, OK, FAILED).
- Сумма операции — сумма транзакции в оригинальной валюте.
- Валюта операции — валюта, в которой была произведена транзакция.
- Сумма платежа — сумма транзакции в валюте счета.
- Валюта платежа — валюта счета.
- Кешбэк — размер полученного кешбэка.
- Категория — категория транзакции.
- MCC — код категории транзакции (соответствует международной классификации).
- Описание — описание транзакции.
- Бонусы (включая кешбэк) — количество полученных бонусов (включая кешбэк).
- Округление на «Инвесткопилку» — сумма, которая была округлена и переведена на «Инвесткопилку».
- Сумма операции с округлением — сумма транзакции, округленная до ближайшего целого числа.

## 🧪 Тестирование
### Запуск тестов:
```
# Базовый запуск тестов
python -m pytest tests/

# Запуск с подробным выводом
python -m pytest -v tests/

# Запуск конкретного тестового файла
python -m pytest tests/test_utils.py
```
### Покрытие кода
#### Проект настроен для измерения покрытия кода тестами:
```
# Генерация отчета о покрытии в консоли
pytest --cov=src

# Подробный отчет с HTML выводом
pytest --cov=src --cov-report=html

# Минимальное покрытие 80%
pytest --cov=src --cov-fail-under=80
```
#### После запуска с --cov-report=html будет создана папка htmlcov/ с детальным отчетом. Откройте htmlcov/index.html в браузере для просмотра:

1) Общее покрытие - процент протестированного кода

2) Покрытие по файлам - детализация по каждому модулю

3) Цветовая маркировка:

- 🟢 Зеленый - код покрыт тестами

- 🔴 Красный - код не покрыт тестами

- 🟡 Желтый - частичное покрытие


### Структура тестов:
```
tests/
├── test_utils.py     # Тесты утилит
├── test_views.py     # Тесты представлений  
├── test_reports.py   # Тесты отчетов
└── test_services.py  # Тесты сервисов
```
